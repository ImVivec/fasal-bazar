# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Mandi (wholesale market) price app for farmers in Malwa (MP) and Hadoti (Rajasthan). Next.js 16 App Router +
React 19 + TypeScript on Vercel Hobby, MongoDB Atlas M0, data from the undocumented Agmarknet 2.0 API.
Crop-first UI in Hindi and English, login gated by admin approval. `README.md` has the product, setup,
deploy and "Later" list; `docs/DB_CHANGES.md` is the database changelog; `docs/legacy-context/` holds the
original brief and findings about the old app and data sources.

## Commands

```bash
npm run dev                       # Next dev server (HMR)
npm run build && npm run start    # production build; .claude/launch.json "web" runs `start` on :3000, so build first
npm test                          # vitest run (all of test/**/*.test.ts)
npx vitest run test/ingest.test.ts            # one file
npx vitest run -t "buildDailyOps"             # tests matching a name
npm run typecheck                 # tsc --noEmit (there is no lint script)

npm run db:setup                  # idempotent: creates collections, prints stats; never drops
npm run admin:create              # interactive: admin account (mobile + 6–8 digit PIN)
npm run daily                     # the daily ingestion job (same as GitHub Actions)
npm run backfill -- --until=YYYY-MM-DD [--from=YYYY-MM-DD]   # resumable day-by-day history
npm run gen:master [-- --refresh] # regenerate src/lib/master.ts (crops/districts/mandis)
python3 scripts/crop-photos.py [slug…]   # regenerate public/crops/*.webp + src/lib/crop-photos.ts
```

- Scripts need `.env.local` (`MONGODB_URI`, `AUTH_SECRET` 32+ chars, optional `MONGODB_DB`, `CRON_SECRET`).
  They run via `tsx --conditions=react-server --env-file-if-exists=.env.local`. The `react-server` condition is
  required because `src/lib` modules import `server-only`; any new script that imports from `src/lib` must use
  the same flags (copy an existing `package.json` entry).
- Tests never touch Mongo: they import only pure modules (`*-core.ts`, `agmarknet.ts` parsers, `session.ts`,
  `password.ts`, `dates.ts`) and set `AUTH_SECRET` in `beforeAll`. Recorded Agmarknet responses live in
  `test/fixtures/`.
- A second database `fasal_bazar_test` exists on the same cluster with test accounts; `.claude/launch.json`
  "web-testdb" serves it on :3001. Prefer it over production for manual testing.
- `npm run convert` is a finished one-time migration (2026-10-04); don't run it again. `npm run recompute:monthly` (rebuild monthly summaries from `daily`) is safe to re-run.

## Architecture

**Data flow**

```
GitHub Actions (.github/workflows/daily-prices.yml, 08:00 + 19:00 IST)
  └─ scripts/daily.ts ─► runDaily() in src/lib/ingest.ts
       ├─ src/lib/agmarknet.ts  fetchDay / fetchMarketList / fetchMsp   (1 call = 1 date × all crops × all mandis)
       └─ Mongo: daily, monthly, meta   via src/lib/db.ts cols()
Pages: src/lib/prices.ts (1–3 _id-range reads) ─► *-core.ts shaping ─► static pages, ISR revalidate = 3600
```

**Module layering in `src/lib`** (the convention to keep)

- `*-core.ts` files are **pure, no I/O**, and are what the unit tests cover: `prices-core` (crop page rows and
  series), `analysis-core` (verdicts, best mandi, seasonality), `arrivals-core` (weekly arrivals), `ingest-core`
  (bulk ops, `cropRange`, `dailyPlan`, watch diffs), `users-core` (phone/PIN validation). Put new logic that
  needs testing here.
- The sibling without `-core` does the Mongo I/O and imports `server-only`: `prices.ts`, `ingest.ts`,
  `users.ts`. `db.ts` is the **only** module that talks to MongoDB; it exports the document types and
  `cols()`, and caches one `MongoClient` on `globalThis`.
- `agmarknet.ts` is the single adapter for the external API. It normalises nulls and string numbers (`num`),
  aggregates varieties per mandi into `[min, max, modal, arrivals]`, and contains the coriander quirk fixes
  (grain-mandi "Coriander(Leaves)" rows count as coriander seed; "Rs./Bundle" leaves are really per quintal).
- `master.ts` is **generated** by `scripts/gen-master.ts` from `scripts/master-src/agmarknet.json`. Never edit
  it by hand. Crops, districts, mandis and their Hindi names live in code and are joined by Agmarknet numeric
  IDs; Mongo stores only IDs. `crop-photos.ts` is likewise generated by the Python script.
- `strings.ts` holds every UI string (`dict(lang)`, `nameIn(crop, lang)`). `dates.ts`: all dates are IST
  `YYYY-MM-DD` strings; charts use days-since-epoch integers (`toDay`/`fromDay`).

**Mongo document model** (only `_id` indexes; every query is an `_id` range via `cropRange()`)

| Collection | `_id` | Body |
|---|---|---|
| `daily` | `"<cropId>:YYYY-MM-DD"` | `m: { "<marketId>": [min, max, modal, arrivals] }` |
| `monthly` | `"<cropId>:YYYY-MM"` (completed months only) | `m: { "<marketId>": [avgModal, daysReported] }` |
| `meta` | `"agmarknet"` (single doc) | job status, `msp`, `fetchedThrough`, `fill` cursor, `active` (crop picker), `marketWatch`, `cropWatch` |
| `users` | 10-digit mobile number | `n, pin (scrypt), d, l, role, st, …` (see `UserDoc` in `db.ts`) |

All writes are idempotent `$set` upserts with one path per mandi, so re-running ingestion never duplicates or
wipes data.

**Routing and auth**

- `src/proxy.ts` (Next 16's replacement for middleware) runs on every non-API request: verifies the HMAC-signed
  session cookie `fb_s` statelessly (no DB call), redirects guests to `/login`, blocks non-admins from
  `/admin`, and **rewrites `/x` to `/<lang>/x`** using the language stored in the session. Public URLs never
  carry a language prefix; `/en/...` and `/hi/...` redirect to the bare path.
- `src/app/[lang]/…` is the logged-in app, `src/app/(auth)/` is login/signup (guest language from the
  `fb_lang` cookie, default Hindi). `src/app/api/*` routes do their own auth (`getSession()` or the
  `CRON_SECRET` bearer token for `/api/ingest`).
- Pages under `[lang]/[crop]` are **fully static per (lang, crop)**: `generateStaticParams` over
  `LANGS × CROPS`, `dynamicParams = false`, `revalidate = 3600`. District filtering happens in the browser.
  Chart data comes from static route handlers `/<crop>/history` and `/<crop>/arrivals` whose payloads are
  language-neutral (names are filled in client-side) so one cached response serves both languages.
- Server actions live in `src/lib/auth-actions.ts`; session helpers (`requireSession`, `requireAdmin`,
  `startSession`) in `auth.ts`; cookie signing in `session.ts`. Login is mobile + PIN hashed with scrypt;
  5 wrong tries lock for 30 minutes. New accounts are `pending` until an admin approves them on `/admin`.
- Client-side persistence: `useSessionState` (sessionStorage, synced across components) for UI choices like
  district filter and chart range; `settings.ts` (localStorage) for favourite crops. The non-httpOnly `fb_ui`
  cookie mirrors display-only session info for client components.

## Project rules

These come from the original brief (`docs/legacy-context/00_AGENT_PROMPT.md`) and are still in force.

- **Free tiers only** (Vercel Hobby, Atlas M0 = 512 MB). Minimise stored bytes, document count, indexes,
  Mongo round-trips and function invocations. Choose cheap over clever; target is ~20–50 users.
- **Collections and indexes are created only in `scripts/db-setup.ts`.** Never create them ad hoc in app code.
- **Every DB change** (collection, index, document shape, data migration) must be logged in
  `docs/DB_CHANGES.md` with what, why and rough storage cost, and stated explicitly to the user.
- **Never drop or delete collections or data without asking first.** This includes the test database.
- Mongo and Agmarknet are reached only from server code (`import 'server-only'`); secrets never reach the browser.
- Agmarknet rate-limits bursts (HTTP 429 for ~5 min): keep calls sequential with the existing ~1 s pause and
  the honest `User-Agent`. Never bypass a captcha or scrape behind a login.
- Features outside the current scope go in the README's "Later" list rather than being built.
- Keep `turbopackScopeHoisting: false` in `next.config.ts`; it works around a documented client-navigation
  crash in Next 16.3.8.

## Adding scope

Districts, mandis and crops are chosen in `scripts/gen-master.ts` (`DISTRICTS`, `CROPS`, `MARKET_HI`). After
editing, run `npm run gen:master -- --refresh` (fails loudly if a mandi lacks a Hindi name), then backfill.
The daily job's market watch and crop watch (shown on `/admin` and as GitHub Actions warnings) flag candidates;
prices for newly discovered mandis are already stored before they are added to the code list.
